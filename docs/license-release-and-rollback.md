本次更新保持四个项目的原目录结构，通过独立分支提交，由管理员审核后合入 main。推送代码不会部署服务器、执行数据库迁移或开启自动邮件。

## 分步部署

这些项目可以在不同服务器上。先记录各服务器的实际目录、启动方式、运行版本和所连接的数据库，再按原部署方式更新。

1. 备份现有数据库、各服务的代码或运行产物、私有配置和定时任务；保留旧 license-notify 目录及其状态文件。
2. 检查已有表、字段及索引后，仅执行缺少的增量迁移。已有数据库禁止执行完整 `agent_ai/database/schema.sql`；申请表的 ALTER 迁移不得重复执行。
3. 先更新管理后台并验收历史申请、筛选、状态、拒绝理由和文件匹配。保持 `LICENSE_SEND_ENABLED=false`。
4. 协调 Java、Web 和小程序上线并验收。新 Java 要求登录及官网提交标记，旧版客户端尚未更新时会提交失败，小程序审核时间须纳入安排。
5. 核对历史 FAE 通知、邮件地址和队列后，停用旧早间任务，再启用新的计划任务与发送开关，避免两套任务同时运行。

详细步骤见 [后台与邮件部署](license-delivery-deployment.md)、[Java 和两端个人中心部署](license-portal-deployment.md)、[Web 50 次资料提示](question-profile-limit.md)。生产配置按服务器实际值填写，不直接覆盖。

## 回滚

- **尚未合并或部署**：main 和服务器仍保持原版，可关闭合并请求，无须恢复数据库。
- **已合并，需撤销代码**：由管理员针对本次合并创建 revert 提交及新的合并请求，保留完整历史，不强制推送或重置公共分支。
- **已部署，需恢复服务**：先关闭发送开关、停用新定时任务，再按原发布方式恢复备份的代码或运行产物与配置；依赖新的 Java 接口的前端须协调恢复。小程序需通过其发布流程回退。
- **数据库保留**：不要删除新表、新字段、上传文件和邮件去重记录，不把上线后的业务库整体覆盖为旧备份，以免丢失新申请或触发重复发信。旧代码恢复后保留增量结构，另行验证兼容性。
- 已发送的邮件无法通过代码回滚撤回；旧早间脚本只有在核对已通知记录后才可恢复。

Git 保存的是代码版本，不代替数据库、生产配置和上传附件的备份。

## Windows 上传入口补充（后台 v5.2）

新版完整后台包支持继续双击 `deploy/upload-admin-console.cmd`。保留原 `deploy/upload-admin-console.psd1`，先在本地后台目录运行 `npm ci`。PS1 调用新的远端脚本，自动检查工作流表，缺表时先用 mysqldump 备份数据库，再补建缺失表；成功后将新版本设为准备模式并保留旧工程备份。权限不足、结构不符或备份失败会在切换前停止。Java 的 ALTER 迁移仍单独执行。详见 [后台自动部署说明](../Pango-Admin-Console/deploy/README.md)。

此修复只更新后台部署及其测试/文档，Web、小程序、Java 业务代码不变。已验证本地构建、准备检查、隔离 MySQL 备份/建表/重复运行、缺 CREATE 权限中止，以及模拟构建/启动失败回退；Windows PowerShell 到真实服务器的完整 SSH 部署尚未执行。
