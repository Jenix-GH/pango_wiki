# Web 50 次问答后完善个人信息（最终范围：只修改 Web）

按用户确认，本次只修复 Web。小程序原有 50 次判断保持原样；Java 保留原有次数/资料接口，没有新增后端限制或资料接口。此前扩大到小程序和 Java 的中间实现已撤回，v6 中间包不作为交付版本。

## 规则

已登录用户累计完成 50 次问答后，第 51 次需要填写个人信息中的“公司或学校”；填写并保存成功后继续使用。访客仍使用原有 10 次规则。计数由已有 Java 接口返回，沿用累计答案条数，不新增数据库字段或迁移，不清零原次数。

## Web 修改

- ChatPage 增加 50 次资料判断。未完善资料的账号在发送前通过现有 `/auth/me` 核对最新次数和资料，以读取小程序中的最新变化。
- 达到阈值直接打开个人资料表单，字段提示为“公司或学校”。空白不能解锁，保存失败保留表单并可重试。
- 继续调用原 `/userinfo/doUpdate`，保留原后端要求的 wxCode 等用户字段。旧接口返回 count=null 时保留已有计数，不将历史次数误设为零。
- 未发送的问题和已选图片保留，由用户保存资料后再次点击发送。
- 输入期间避免连续点击产生重复的资料核对/发送请求。
- 这是 Web 前端行为校验，与现有小程序方式一致，没有宣称新增服务器强制配额。

本轮实际修改 6 个原有 Web 文件：ChatPage.tsx、ChatInput.tsx、SettingsPanel.tsx、SettingsPanel.css、AuthContext.tsx、api/client.ts（资料返回值类型）。原 Web API 地址不变，流式解析逻辑不变。
